# Wolke AI Website - Content Decisions Needed

These items need founder input before the frontend developer should finalize the pages.

## 1. Domain

Confirm exact production domain:

- `https://wolke.ai/`?
- `https://www.wolke.ai/`?
- another domain?

This is needed for:

- `sitemap.xml`
- `robots.txt`
- canonical URLs
- Open Graph URLs
- Google Search Console

## 2. Public contact details

Confirm:

- Public phone number
- Public email address
- Whether phone should be shown globally or only on contact section
- Appointment booking link, if any
- Service region: local, Germany, Europe, global?

## 3. Legal details

Confirm:

- Legal company name
- Address for Impressum
- Responsible person
- VAT ID, if applicable
- Register/court details, if applicable
- Privacy contact email

Do not publish the legal page without this.

## 4. Pricing approach

Choose one for iteration 1:

### Option A - no prices yet

Use package cards with `Custom quote after assessment`.

### Option B - starting prices

Show `Starting from ...` for each package.

### Option C - pilot offer

Use a controlled version of the archive pitch-deck idea: early partners receive a pilot discount in exchange for feedback, use-case validation, and permission to create anonymized case material.

## 5. Proof and achievements

Confirm what can be publicly claimed:

- Can we say `already helped businesses query ERP data in natural language`?
- Can we mention SKU movement tracking?
- Can we mention B2B customer order visibility?
- Are there any numbers we can publish?
- Are customer names/logos allowed? If not, use anonymized proof.

## 6. Language

Choose:

- English only
- German only
- English first, German later
- English and German from iteration 1

## 7. Target segment wording

Confirm the first wedge:

- FMCG wholesalers
- Food importers
- Warehouse-led distributors
- B2B retailers and suppliers
- Broader ERP-heavy businesses

Recommended iteration 1 wording:

> Built for FMCG wholesalers, importers, distributors, and warehouse-led businesses.

## 8. Product specificity

Confirm which features are current vs exploratory.

Current capabilities likely safe to present:

- Natural-language data querying over business data
- AI assistant for owners
- SKU movement tracking
- Improved customer order visibility

Exploratory / assessment use cases:

- Inventory expiry management
- Seasonal demand prediction
- Optimal pricing support
- Automated restocking alerts

## 9. Analytics and Hotjar

For iteration 1, recommended: no tracking yet, or only Search Console.

By iteration 4, confirm:

- Google Analytics account / GA4 measurement ID
- Google Tag Manager container ID, if using GTM
- Hotjar site ID
- Cookie consent approach
- Privacy policy wording

## 10. Visual assets

Decide whether to use:

- Real warehouse photos
- AI-generated warehouse/dashboard mockups
- Custom diagrams only
- A mix

Recommended: use custom dashboard/ERP/assistant mockups first. They communicate the product better than generic stock photography.
